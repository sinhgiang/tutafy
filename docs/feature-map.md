# Feature map

Tutafy: booking, lessons and payments for private tutors (Next.js 16, Supabase, Polar for plans).

## Features

- Tutor settings (profile, booking page, payments, plan): `src/app/(dashboard)/settings/page.tsx`; the tutor opens it from the sidebar "Settings", Payments tab (`/settings?tab=payments`).
- Card payments through Stripe Connect (Pro plan): `src/app/api/stripe/connect/` (`onboard` starts onboarding, `status` says whether Stripe is switched on); on/off logic and customer wording in `src/lib/stripe/availability.ts`; plan gate in `src/lib/api-guard.ts`.
- Tutor money display: a tutor's prices are in `tutors.currency` (Settings, Default Currency). `src/lib/currency.ts` formats every amount (`formatMoney`, `currencySymbol`; dong and yen without cents), `src/lib/tutor-currency.ts` loads the tutor's currency for the dashboard, Payments, Reports and Calendar pages, and `src/lib/admin-revenue.ts` builds the owner's `/admin/revenue` page (one total per currency). `lessons.currency` and `invoices.currency` are never written, so no page reads them. After booking, `/api/bookings` answers with the saved `price` and the tutor's `currency`; the booking page's payment panel prints that, which is what Stripe charges.
- Student booking and paying: `src/app/book/[slug]/BookingForm.tsx`; the student gets there from the tutor's public booking link `/book/<slug>`. Card payment marked paid: `src/app/api/webhooks/stripe-connect/route.ts` (Stripe Connect webhook, signing secret `STRIPE_CONNECT_WEBHOOK_SECRET`, closed with 503 without it; trusts only the session recorded in `lesson_card_payments`, migration `017_lesson_card_payments.sql`, not applied yet; one open session per lesson). Card checkout: `src/app/api/stripe/checkout/route.ts` (the amount comes from the lesson's price and the currency from the tutor's `tutors.currency`, the one the booking page shows; `lessons.currency` is never written, so it is not read), `src/app/api/subscriptions/checkout/route.ts`.
- Plans and gating: `src/lib/plans.ts`, `src/lib/guard.tsx`; upgrades go through Polar (`/upgrade`).
- Operator-only admin area: `src/app/(admin)/admin/` (may name environment variables; customers never see it). Only the admin account gets in: the proxy (`src/proxy.ts`), the layout and each data page call the check in `src/lib/admin.ts` / `src/lib/admin-guard.ts`; anyone else goes to `/dashboard`, signed-out visitors to `/login`.
- Admin Buyers (tutors on Pro or Academy, with totals): `src/app/(admin)/admin/buyers/page.tsx`, data in `src/lib/buyers-data.ts`; opened from the admin sidebar "Buyers" (`/admin/buyers`). The Plan column lives on `/admin/tutors`. The tutors table has no country column, so Buyers shows the timezone.
- Super admin (the owner's page: buyers with country, first source, pages in order, last page before checkout and order result; funnel by source; date filter): `src/app/(admin)/super-admin/page.tsx`, data in `src/lib/super-admin-data.ts` (it reuses `loadBuyers` from `src/lib/buyers-data.ts`) and `src/lib/journey.ts`; opened from the admin sidebar "Super admin" (`/super-admin`), admin account only (proxy + layout + the page itself).
- Visitor journey (only after the visitor accepts cookies): browser `src/components/VisitorTracker.tsx` and `src/lib/track-client.ts`, server `src/app/api/track/route.ts` and `src/lib/visitor-tracking.ts`; source rules in `src/lib/visitor-source.ts`, page list in `src/lib/track-path.ts`; the Polar webhook adds the paid order. Tables are in `supabase/migrations/015_visitor_tracking.sql` (written, NOT applied to the real database until the owner decides); the Privacy page describes it.
- Landing page facts and AI-assistant files: prices, feature texts, FAQ and the key-page list live once in `src/lib/site-content.ts`; the landing page (`src/app/page.tsx`) renders them, `src/lib/seo.ts` turns them into the page's JSON-LD (SoftwareApplication, Organization, WebSite, FAQPage), and `src/lib/llms.ts` builds `/llms.txt` and `/llms-full.txt` (routes `src/app/llms.txt/route.ts`, `src/app/llms-full.txt/route.ts`; blog list from `src/lib/blog.ts`). Change a price or FAQ answer in `site-content.ts` only. `src/app/sitemap.ts` gives static pages no `lastModified` (blog posts and the blog index use real post dates); `src/app/robots.ts` stays open to every crawler. Tests: `tests/seo-llms.test.ts`.

- Search-engine metadata (T-0623): the ONE main address is `SITE_URL` = `https://www.tutafy.com` in `src/lib/site-url.ts` (a constant, never read from `NEXT_PUBLIC_APP_URL`); `src/app/robots.ts`, `src/app/sitemap.ts`, the JSON-LD (`src/lib/seo.ts`), `/llms.txt` and the blog page all use it. Every public page's title, description, canonical, og/twitter text and `noindex` rule is in `src/lib/page-meta.ts` (`PAGE_SEO` for fixed pages, `BLOG_SEO` for each post; the post's own `title` stays the visible headline); pages call `pageMetadata('<key>')` / `blogPostMetadata(slug)`. Client pages get theirs from a layout (`(auth)/login/layout.tsx`, `(auth)/register/layout.tsx`, `student/login/layout.tsx`, `tutors/(directory)/layout.tsx`). `/login`, `/register`, `/student/login` are noindex and not in the sitemap; `/register` gets its one `<h1>` (hidden on screen) from its layout. Limits: title 20-60, description 70-155 characters. Add a page: add it to `PAGE_SEO`, to `sitemap.ts` (unless noindex) and call `pageMetadata` in it. Tests: `tests/seo-metadata.test.ts`.

- Google tag (GA4 + Google Ads, only after the visitor presses Accept in the cookie banner): `src/components/Analytics.tsx` renders it, rules in `src/lib/google-tag.ts` (one gtag.js load, one `config` per distinct ID; GA4 id from `NEXT_PUBLIC_GA4_MEASUREMENT_ID`, empty means the built-in public `G-` id; `NEXT_PUBLIC_GA_MEASUREMENT_ID` is the Ads `AW-` id and a `G-` value there is not loaded twice). The Tutafy Ads id `AW-18335043737` is always configured (`ADS_ID`), and the Ads sign-up conversion is a real `gtag('event','conversion',{send_to})` call (`sendAdsSignupConversion`, label in `ADS_SIGNUP_CONVERSION`; never push an array to `dataLayer` by hand, gtag.js ignores it). GA4 events `sign_up` and that conversion are sent from `src/app/onboarding/page.tsx` after a new account lands with `?signup=1`; `sign_up` and `begin_checkout` (`trackCheckoutClick` in `src/lib/track-client.ts`) carry no personal data. The tag never reports the real address of a page (T-0637): `config` has `send_page_view: false`, the page view is sent by hand (`sendGooglePageView`, 250 ms after each page change) with the path from `src/lib/google-page.ts` (no code, no id, no query; only `utm_*` and `gclid` on a public page; `/portal/[token]`, `/students`, `/book/[slug]`), nothing is loaded or sent on a page that opens private data (`isSecretPath`: the student portal, record ids, admin, `/student/dashboard`, `/upgrade/success`), and a tag that is already running is switched off there with `window['ga-disable-<id>']`. Anything new that puts an address in front of Google or Meta must go through `google-page.ts`. In GA4 also turn off "Page changes based on browser history events" (Admin, Data streams, Enhanced measurement). Privacy page: "Cookies & analytics". Tests: `tests/google-tag.test.ts`, `tests/google-page.test.ts`.

## Run and check

- Open it: `npm run dev`, then http://localhost:3000. Needs `.env.local` with the Supabase settings (copy `.env.example`; never commit it).
- Test account: none recorded yet. A Pro test tutor is needed to see the Settings > Payments > Stripe box; ask the owner for a throwaway account. Do not use a real tutor's login.
- Main flow to go through: sign in as a Pro tutor, open Settings, Payments tab, look at the Stripe Connect box. With the platform Stripe off the Stripe Connect box is not shown at all; with it on it shows the "Connect Stripe account" button. The "Card payment link (Stripe Payment Link)" field above it is always shown.
- Tests: `npm test` (node's built-in runner, `tests/*.test.ts`, no browser needed). The migration test runs the SQL on an in-memory Postgres (PGlite), never on a real database.
- Screenshot: the helme-browser tools against the running dev server, saved as the Helme task asks.
