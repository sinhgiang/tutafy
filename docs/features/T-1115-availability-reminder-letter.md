# T-1115: The tutor email tool sends a second letter - the free hours reminder

`/super-admin/announcement` (T-1064) now has two letters, chosen at the top of the page ("Which letter": "Profile letter" and "Free hours reminder"; `?campaign=<id>` in the address, the profile letter when nothing is named). Everything below the choice (setup checks, the test mail, Start, Stop, the status) works on the letter on screen. Nothing was sent when this was built, and nothing runs by itself.

- **The new letter.** Subject "Your Tutafy page is live, but students cannot book you yet"; the owner-approved draft (Brain `inbox/tutafy-availability-reminder.md`), word for word, under 150 words, "Hi <first name>,". It tells the tutor to press one of the four ready-made weeks in the "Pick a week in one tap" box of T-1105 (pull request #118, merged before this branch was made). Rendered by `renderAvailabilityReminder` in `src/lib/tutor-announcement.ts`.
- **Who gets it.** The tutors the profile letter would go to (page on, a real introduction, not a test account, not a copy of another profile, a plain address, not unsubscribed) MINUS every tutor who has at least one row in `availability`, the same test as the dashboard card (`src/lib/directory-setup.ts`). Hours are asked one tutor at a time with `limit 1`, so a long week can never be cut short and read as "none"; a failed answer is a failed read and nothing is queued (`loadAnnouncementRecipients(db, campaign)`). On 30 Oct 2026 that was 21 tutors. The number is shown above the Start button before it is pressed (a number only: no name, no address) and Start must be given the same number.
- **One record per letter.** A campaign id is a fixed list (`CAMPAIGN_IDS`: `tutor-profile-2026-10` and `tutor-availability-2026-10`; `parseCampaign` accepts exactly those, `campaignOf` reads the request body: nothing named is the profile letter, a name that is not in the list is a 400). The tables of migration 030 already hold everything per campaign (the campaign id is the first column of both keys), so **there is no new migration**. A tutor who got the profile letter still gets this one; a tutor already queued for this one is never queued for it again; the mail service's idempotency key names the campaign.
- **Every safety rule of the old letter holds, per letter.** The test mail goes only to the admin's own session address, marked `[Test]`, and unlocks only ITS letter for 7 days (the profile letter's test does not unlock the new one); Start shows the confirm box with the number and the server refuses a different number (409 with the real one); mails go exactly 3 minutes apart through the mail service's own `scheduledAt`; Stop cancels only the mails of the letter on screen; nothing stores or shows an address or a name; each route checks the admin and the Origin first.
- **Three minutes between ANY two mails.** `startAnnouncement` now also looks at the other letter's mails that still wait (or are being handed over) and starts after the last of them plus 3 minutes, so starting the second letter while the first is still going never puts two mails closer than 3 minutes.
- **Files.** `src/lib/tutor-announcement.ts` (the letter, the campaign list, `withoutHours`), `src/lib/tutor-announcement-run.ts` (all five functions take a `campaign`, default the profile letter), the three routes under `src/app/api/admin/announcement/`, `src/app/(admin)/super-admin/announcement/page.tsx` and `AnnouncementControls.tsx` (the chooser, the subject and "who gets it" lines; the buttons send the campaign), `src/lib/admin-i18n.ts` (`ann.letter*`, `ann.subjectLabel`, `ann.who*`, both languages).
- **Tests.** `tests/tutor-announcement-hours.test.ts` (15 tests: the fixed campaign list, the letter word for word and in the brand voice (the forbidden words are read from `docs/brand-voice.md`), the letter names the four weeks of the box, recipients without hours (another tutor's hours do not hide a tutor, a tutor who presses a one-tap week leaves the list, a 30-row week still counts as hours, a failed read stops it), a tutor who got the profile letter still gets this one, once, three minutes after the other letter's last waiting mail, the number shown and the number Start needs, the test mail, Stop of one letter only, the three routes with a campaign (401, 403, cross-site, 400 for an unknown one), the page in both languages). `tests/tutor-announcement.test.ts` (30 tests) is unchanged and still passes: the profile letter behaves as before. Mutations tried: hours filter removed, the other letter's waiting mails ignored, the claim stored under the profile id, the test unlocking every letter; each turns tests red.
- **Not done.** A tutor who adds hours after being queued still gets the mail (it is already with the mail service; Stop takes back the ones not yet gone). Delivery is not read back. The two letters are not blocked from reaching the same tutor close together; the page says to wait a few days. The letter's words are in code, so a changed letter is a code change.
